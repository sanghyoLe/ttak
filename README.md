# 딱.

Perfect Fit 영상처럼 보이지만, 사용자가 직접 끼우는 순간 절대 맞지 않는 3D 장난감 게임입니다. 기존 `useless-skills`와 별개인 Apps in Toss 프로젝트입니다.

Three.js로 실제 입체 모델, 조명, 그림자를 렌더링합니다. 홈에서 완벽하게 맞는 3D 데모를 보고, 게임에서는 마우스나 손가락으로 같은 물체를 직접 움직입니다. `다른 각도`로 시점을 바꿀 수 있고, 미리보기는 일시 정지할 수 있습니다.

네 장면에서 완벽하게 맞을 것 같은 순간을 네 번 만들고, 네 번 모두 일부러 망칩니다.

- 마지막 한 조각: 넣는 순간 조각이 커졌다가 튀어나옵니다.
- 가운데 홈: 원을 넣으려는 순간 홈이 움직입니다.
- 마지막 칸: 마지막 블록을 넣자 옆 블록들이 도미노처럼 넘어집니다.
- 끝까지 밀기: 닫힌 서랍이 다시 튀어나오며 내용물도 들썩입니다.

성공할 수 없는 것이 규칙입니다. 홈 근처까지 옮겨 놓았을 때 실패 연출이 시작되고, 단순히 탭하거나 엉뚱한 위치에 놓으면 처음 위치로 돌아갑니다. 실패 장면은 자동으로 넘어가지 않습니다. 사용자가 재시도하거나 다음 장면을 고르며, 재시도도 실제 도전 횟수에 포함됩니다.

블록·도미노·서랍은 마지막에 눌러 마무리해야 하며, 원형 홈은 접근하면 두 번 피합니다. 잠깐 100%와 ‘맞음’ 판정을 받은 뒤 반전이 일어납니다. 각 장면은 재시도에 따라 세 가지 반전을 순환하므로 총 12가지 결과를 볼 수 있습니다. 참고한 일본 게임과 구체적인 조작 원칙은 [게임 감각 노트](docs/GAME_FEEL.md)에 정리했습니다.

키보드는 방향키로 이동하고 Enter로 끼웁니다. 소리를 끌 수 있고, 모션 줄이기 설정에서는 자동 데모와 튀어 오르는 연출을 줄입니다. 화면이 숨겨지거나 조작이 멈추면 렌더링도 쉬며, 3D 화면을 열 수 없는 기기에서는 다시 불러오기 안내가 나타납니다.

## 로컬에서 보기

```bash
pnpm install
pnpm dev
```

브라우저에서 `http://localhost:5190`을 엽니다.

## 토스 앱으로 준비하기

1. Apps in Toss 콘솔에서 앱 이름을 `딱.`으로 만듭니다.
2. 콘솔에서 정한 고유 `appName`을 `src/app-config.ts`의 `TOSS_APP_NAME`에 입력합니다.
3. `pnpm dev:toss`로 샌드박스 환경을 확인합니다.
4. 게임물 등급분류 절차를 완료하고 콘솔에 결과를 등록합니다.
5. 아래 명령으로 업로드 파일을 만듭니다.

```bash
pnpm build
```

루트에 생성된 `.ait` 파일을 콘솔에 업로드합니다. 앱 아이콘 원본은 `public/app-icon.svg`입니다.

## 확인 명령

```bash
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm build
```

완료한 판 수와 누적 실패 횟수는 브라우저에서는 `localStorage`, 토스 앱에서는 SDK `Storage`에 저장됩니다. 기기가 무음이거나 오디오 재생이 제한되어도 모든 조작과 화면 전환은 그대로 동작합니다.
